TASK 1: supabase/migrations/015_photo_check.sql
a) Table photo_checks (photo_url text primary key, user_id uuid, analysis_status text check in ('ok','unavailable'), detected_category text, confidence numeric, is_civic_issue boolean, is_real_photo boolean, suggested_severity text, reason text, image_sha256 text, created_at timestamptz default now()). Enable RLS and create NO policies for anon or authenticated (private: it holds user ids). Add an index on image_sha256. Only the service role writes to it.
b) photo_confidence_threshold() returns numeric = 0.7 (plain immutable, plain-language comment: how sure the AI must be before a mismatch is blocked or a match is trusted; the single constant to change).
c) Insert one row into app_settings: key 'photo_check_fail_mode', value 'open' (on conflict do nothing). Comment: 'open' = if the AI is unavailable the report is allowed and marked "photo not verified"; 'closed' = it is blocked.
d) photo_verdict(p_photo_url text, p_category text) returns jsonb, SECURITY DEFINER, set search_path = public, extensions, executable by no client role (revoke from public, anon, authenticated). Returns {verdict, code, detected_category, suggested_severity, confidence}. verdict is 'pass', 'review', 'reject' or 'unchecked'. Rules, in this order, with a comment on each:
   1. No photo_checks row for the url: reject, code 'missing'.
   2. analysis_status = 'unavailable': 'unchecked' with code 'unavailable', or reject with code 'unavailable' when photo_check_fail_mode = 'closed'.
   3. is_real_photo = false: reject, code 'not_real'.
   4. is_civic_issue = false: reject, code 'not_civic'.
   5. Reused image: another photo_checks row with the same image_sha256 but a different photo_url that is already used in the reports table: reject, code 'reused'.
   6. Category 'other': pass, code 'ok'.
   7. detected_category = p_category: pass if confidence >= photo_confidence_threshold(), otherwise review with code 'low_confidence'.
   8. detected_category differs: reject with code 'mismatch' if confidence >= photo_confidence_threshold(), otherwise review with code 'low_confidence'.
e) check_photo(p_photo_url text, p_category text) returns jsonb, SECURITY DEFINER, granted to authenticated only. Raise if auth.uid() is null. If the photo_checks row does not exist or its user_id is not auth.uid(), return reject with code 'missing'. Otherwise return photo_verdict(...). Never return user ids.
f) Trigger function and trigger enforce_photo_check, BEFORE INSERT on reports, SECURITY DEFINER with search_path set:
   - If auth.uid() is null, return NEW unchanged (SQL Editor and seed scripts must keep working).
   - Look up the category from issues using NEW.issue_id. Require a photo_checks row for NEW.photo_url whose user_id equals NEW.user_id, else raise 'Photo has not been checked'.
   - Call photo_verdict. If verdict is 'reject', raise an exception with the message 'Photo check failed: ' || code. Otherwise set NEW.ai_suggested_category and NEW.ai_suggested_severity from the stored detection and continue.
   - It must not interfere with the existing triggers on reports (rate limit, score recompute).
g) officer_photo_checks(p_issue_id uuid) returns jsonb array, callable by officer or admin only (use officer_scope() from 010 and the same scope check as officer_issue). One element per report on the issue: photo_url, verdict, code, detected_category, confidence, created_at. Never return user ids.
